# Where Matchmate goes next

The direction is broader than match chat: conversations with **matches, teams and stadiums**, supported by a personal football guide and eventually voice. The following areas describe intended work, without promising a delivery date or implying that they are implemented.

The live goal is for incoming football observations to update a shared pitch, calculated statistics, insights and conversation. Recorded and generated demonstration inputs let the prototype test parts of that experience while live sources and sustained processing remain to be connected and verified.

The current replay experience includes half-time/full-time recaps, both-match Story passages and Explain this moment. Story grouping and source summaries remain code-owned; Decision-1 passage/data classification is postponed. The next steps build on these capabilities while keeping generated illustration separate from real football evidence.

1. **Strengthen answer reliability.** Improve subject/date routing and multilingual explanations using representative football questions. Keep unsupported answers, source disagreements and missing coverage visible.
2. **Prepare a reproducible demonstration.** Resolve source-pin and input dependencies, make approved inputs practical to prepare, and validate a coherent, clearly labelled synthetic demonstration through the shared pipeline. Submission data choices and any export remain separately reviewable.
3. **Connect permitted live sources and extend coverage.** Add supported real reference data and a structured-feed adapter while retaining source, timing and quality distinctions. Video-only input additionally needs continuous detection, tracking and identity/quality integration; the offline tools do not implement that service. Establish access, coverage and sustained behavior before presenting a real-time experience. The [video-to-replay workflow](VIDEO-TO-REPLAY.md) explains the preparation path and its limits.
4. **Deepen team and stadium conversations.** Build on existing club and ground context to explore identity, history, style and place when the evidence supports it.
5. **Add a personal guide with consent.** Explore saved preferences, private memory and useful follow-ups, with clear account controls. A browser language choice or temporary Fan/Analyst mode is only a small presentation preference today.
6. **Bring the conversation to voice.** Add voice after the data flow, answer reliability and text experience are strong enough to support it.

The common rule is to improve the experience without letting an attractive explanation outrun its evidence. Read [what works today](CAPABILITIES-AND-LIMITATIONS.md) before treating any roadmap item as available.
